# 合并抵消检查

## Overview
在合并报表出表前，校验合并工作底稿的抵消分录是否合规——每笔抵消分录借贷平衡、四类抵消（往来/收入成本/未实现利润/长投权益）齐全、合并数=个别报表加总±抵消净额守恒。核心验收判据是**恒等式（借贷平衡）+ 白名单（四类齐全）+ 守恒（合并轧账）**三者叠加，确保合并报表不虚增虚减、抵消无遗漏无错漏。

## 数据敏感性
合并数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始财务数据，只看结果摘要；轧账校验在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **借贷平衡（恒等式）** ⭐ | 每笔抵消分录 Σ借 == Σ贷 | 不等 → 分录错误 |
| **类型白名单** ⭐ | 四类抵消齐全（往来/收入成本/未实现利润/长投权益）| 缺 → 抵消遗漏 |
| **合并守恒** ⭐ | 合并数 == 个别加总 + 抵消净额；合并试算差 == 个别报表不平 + 抵消分录不平 | 不等 → 轧账错误 |
| **交叉白名单** | 抵消类型 × 允许科目（如往来抵消只能用应收/应付/其他应收/其他应付）| 否 → 分录错误 |
| **来源一致** ⭐ | 抵消金额 == 从往来台账、期末存货、子公司报表与工商持股比例独立重算的预期值（含少数股东权益）| 不等 → 金额错误 / 漏做抵消 |
| **个别报表试算平衡** | 各主体 Σ借方性质 == Σ贷方性质 | 否 → 个别报表错误 |
| **合并范围** | 集团股权台账 == 工商登记；报表主体 == 控股（>50%）子公司清单 | 否 → 不该合而合 / 该合未合 |

## Workflow

### Step 1: 加载安全契约
- **Mode**: `deterministic`
- **Tool**: `load_skill`；随后按 financial-local-safety Step 1 用 `folder_list`、`list_outposts` 做前置校验
- **Input**: 无
- **Output**: 已加载 financial-local-safety

### Step 2: 读取个别报表与抵消分录
- **Mode**: `agentic`
- **Input**: `{{data_dir}}`
- **Output**: 个别报表按科目 + 抵消分录明细
- **Validate**: 两表非空，科目编码/借贷方/抵消类型字段齐全
- **On failure**: 抵消类型取值须能映射到四类白名单；字段名不符时映射。

### Step 3: 三道校验与合并轧账
- **Mode**: `deterministic`
- **Tool**: `run_python_on_device`（计算只在设备端进行，见 financial-local-safety 铁律 2）
- **Input**: `{{data_dir}}`，调用 `scripts/consolidation_check_v2.py` 的 `check(data_dir)`
- **Output**: 合并工作底稿 + 逐分录结果 + 来源重算差异（逐科目预期/实际）+ 整组漏做清单 + 合并范围问题 + 个别报表试算 + 守恒与差异归因 + 输入指纹与时间戳
- **Validate**: 三道校验状态明确；不平衡分录逐笔列出
- **On failure**: 借贷不平 → 定位到具体抵消分录号；四类缺失 → 提示补充抵消。

### Step 4: 生成讲解页/仪表盘（可选）
- **Mode**: `agentic`
- **Tool**: `run_python_on_device_with_write`（写入授权本地目录）
- **Input**: Step 3 的分析 JSON
- **Output**: 纯 SVG/CSS 自讲解 HTML（三道校验状态卡/四类抵消条/合并底稿表 + TTS 控制栏）
- **Validate**: 单屏不溢出、script 花括号配平、无 lookbehind 正则

### Step 5: 归档
- **Mode**: `deterministic`
- **Tool**: `file_copy`
- **Output**: 存入 `agent_files/artifacts/finance_scenarios/06_consolidation/`

## Lessons Learned
### Do
- 三道判据叠加：借贷平衡（恒等式）+ 四类齐全（白名单）+ 合并守恒，缺一不可。
- 借贷不平定位到具体抵消分录号，方便直接修正。
- 抵消只在合并层面做，不回改个别报表。

### Don't
- 不要放行借贷不平的抵消分录——恒等式一票否决。
- 不要遗漏四类抵消中任一类——白名单校验，缺类即失真。

### Common Failures
- 抵消类型取值不统一（如"收入抵消/内部销售"）：先映射到四类白名单再校验。
- 抵消分录方向/符号错误导致守恒不平：检查借贷方向与科目类别。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 四类抵消是否适用（如无长投则长投权益抵消可豁免）按集团结构确认。
- 未实现利润抵消的计算口径（存货/固定资产内部交易）按会计政策确认。

## 样本数据（演示 · 全部虚构）
示例集团（虚构）：母公司 + 5 家控股子公司（示例子公司A 80%、示例子公司B 60%，其余 100%），另持有联营企业示例联营公司F 30%（权益法，不纳入合并）。集团内往来直接取自关联方往来对账（#5）全平版台账。
- `samples/clean/`：6 家个别报表 79 行，80 笔抵消分录 169 行，四类抵消齐全，全部与来源重算一致
- `samples/error/`：植入 10 处错误（借贷不平 1、往来少抵 1、整组漏抵 1、科目与类型不符 1、按含税金额抵消 1、未实现利润毛利率翻倍 1、少数股东权益漏记 1、个别报表不平 1、联营企业误纳入合并 1、往来台账金额写成千分位无法解析且对应抵消同步少做 1），全部抓出、无误报


## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(合并底稿目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式、白名单、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |
| 合法但不适用 | 白名单 | 值在白名单内但用错场景（如6%与13%都合法，用错税率照样过） | 单字段白名单→交叉白名单（业务类型×允许值）；白名单版本化+生效日 | 🟢可自补 |
| 净额掩盖 | 守恒 | 正负成对错误相互抵消，净差为0但双向各错（如银行多记100+企业多记100） | 分向列示+分向限额；加「笔数守恒」配合金额守恒 | 🟢可自补 |
| **合并范围错误** ⚠️ | 场景特有 | 合并范围本身错（该合未合/不该合而合），恒等式+白名单+守恒三类判据同时失效 | 合并范围与股权比例独立校验+本期主体增减清单逐个说明 | 🟡需外部锚点 |

> **已接入** `scripts/consolidation_check_v2.py`：抵消金额来源重算（交叉一致）、抵消类型×科目交叉白名单、个别报表试算平衡、合并试算差异归因；合并范围校验内置（集团股权台账 ↔ 工商股权登记，识别比例不符、不该合而合、该合未合）。
> **另附** `scripts/blindspot_anchors.py`（🟡半自动·检查+接源建议）：scope_completeness（合并范围主体清单交叉）+ ratio_independent_check（持股比例↔工商股权比例，抓合并判定冲突；无第二源时声明缺口）

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☐ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☐ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☑ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

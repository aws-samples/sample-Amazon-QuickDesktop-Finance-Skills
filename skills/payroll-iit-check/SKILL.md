# 薪酬个税复核

## Overview
按累计预扣法逐人重算个人所得税，校验申报个税是否等于「累计应纳税所得额×适用税率−速算扣除」，验证应纳税所得额组成（累计应发−五险一金−专项附加−减除费用）。核心验收判据是**恒等式 + 税率表白名单**，识别税率错档、专项附加漏减、个税计算错误，双向纠正少缴与多缴。

## 数据敏感性
薪酬含员工 PII。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始薪酬数据，只看结果摘要；个税重算在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **恒等式** ⭐ | 个税 == 累计应纳税所得额 × 税率 − 速算扣除 | 不等 → fail |
| **税率表白名单** ⭐ | 税率/速算扣除 ∈ 法定七级税率表 | 错档 → fail |
| **组成恒等式** | 应纳税所得额 == 应发−五险一金−专项附加−减除 | 不等 → 组成错误 |
| **边界** | 应纳税所得额 ≥ 0 | 负 → 归零 |

## Lessons Learned
### Do
- 用累计预扣法重算：应纳税所得额×税率−速算扣除，税率与速算扣除配对取自同一级。
- 双向纠差：少缴防企业补税风险，多缴护员工到手权益，两个方向都要纠。
- 专项附加、五险一金足额扣减，避免虚高应纳税所得额。

### Don't
- 不要手工估填个税或凭上月推算——必须按累计公式重算。
- 不要错配税率与速算扣除——必须同一级配对。

### Common Failures
- 税率表上限列空表示最高级（inf）：读入时转 float('inf')。
- 累计月份口径不清导致减除费用（5000×月数）错误：确认当前累计月数。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 累计月份、专项附加与专项扣除口径、税率表版本确认。
- 是否含年终奖单独计税、劳务报酬等特殊所得（本skill聚焦工资薪金累计预扣）。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 税率表校验 ⭐ | 提供的税率表逐档与法定基准比对（档次/税率/速算扣除数） | 不符 |
| 累计预扣重算 ⭐ | 逐月累加应纳税所得额 → 查法定表 → 当月应预扣 = 累计个税 − 上月累计 | 不符 |
| 累计一致 | 累计列 == 逐月加总；累计已预扣 == 上月累计个税（链条衔接） | 不符 |
| 减除费用 | 每月 == 5000 | 不符 |
| 专项附加 | 台账 == 备案合计；各项 ≤ 月度上限；有扣除必有备案 | 不符 |
| 边界 | 当月申报个税 ≥ 0 | 不符 |
| 完整性 | 每人每月齐全（1–9 月） | 缺月 |
| 守恒 | Σ当月申报 == 末月累计个税；申报 vs 正确分少缴/多缴 | 自检 |

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(薪酬+税率表目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式、白名单** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |
| 合法但不适用 | 白名单 | 值在白名单内但用错场景（如6%与13%都合法，用错税率照样过） | 单字段白名单→交叉白名单（业务类型×允许值）；白名单版本化+生效日 | 🟢可自补 |
| **专项附加不可验证** ⚠️ | 场景特有 | 专项附加扣除由员工自行申报，企业无第二源可核 | 显式标注「不可验证项」，交人工/税务系统 | 🔴不可闭合 |
| **单向检查漏反向** ⚠️ | 场景特有 | 只查一个方向（如只查少缴/只查我方缺），反向错误（多缴/对方缺）漏检 | 双向列示：正差与负差、A单边与B单边分别输出 | 🟢可自补 |

> **已接入** `scripts/payroll_iit_check_v2.py`：税率表对法定基准逐档校验、累计预扣逐月重算与链条衔接、减除费用、专项附加备案与上限、个税非负、缺月完整性、少缴/多缴分向守恒。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☑ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

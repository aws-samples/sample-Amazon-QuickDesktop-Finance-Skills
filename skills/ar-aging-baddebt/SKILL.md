# 应收账龄与坏账计提

## Overview
按账龄将应收账款分桶（未到期 / 1-30 / 31-60 / 61-90 / 90天以上），并按账龄阶梯计提坏账准备，量化逾期应收、客户欠款集中度与坏账敞口。核心验收判据是**分桶守恒 + 比例计提恒等式**：各桶合计等于总未收，各桶计提之和等于 Σ(桶金额×桶率)，且计提率随账龄单调递增（与 ECL 预期信用损失模型一致）。

## 数据敏感性
应收含客户 PII。**执行前先加载 `financial-local-safety` skill**，本地模式处理。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **分桶守恒** ⭐ | Σ各账龄桶金额 == 总未收余额 | 不等 → 分桶错误 |
| **计提恒等式** ⭐ | Σ各桶计提 == Σ(桶金额 × 桶计提率) | 不等 → 计提错误 |
| **恒等式** | 应收金额 == 已收 + 未收 | 不等 → 数据错误 |
| **单调性** | 账龄越长计提率越高 | 违反 → 计提率表错误 |
| **边界** | 逾期天数 = max(0, 基准日−到期日) | 负值归零 |

## Lessons Learned
### Do
- 账龄用到期日（开票日+信用期）计算，不能用开票日期。
- 分桶守恒 + 计提恒等式两道 assert 必须同时通过。
- 计提率随账龄单调递增，符合预期信用损失（ECL）模型；计提率表参数化，随会计政策更新。

### Don't
- 不要用黑名单式排除或跳桶——分桶必须 MECE。
- 不要放行非单调计提率表——账龄越长风险越高是铁律。

### Common Failures
- 样本核销率高导致未收样本过少：可补充独立应收发票丰富账龄分布（演示场景）。
- 无未收余额列：需先由应收+核销数据计算（可复用 ar-settlement-matching）。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 账龄桶边界（默认 30/60/90）、各桶计提率、信用期天数按客户会计政策确认。
- 是否采用 ECL 三阶段模型或简化的账龄矩阵法，需确认计提口径。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 主数据 | 客户已登记；台账信用期 == 主数据信用期 | 不符 |
| 到期日推算 ⭐ | 到期日 == 开票日期 + 主数据信用期 | 不符 |
| 已收核实 ⭐ | 台账已收 == Σ收款明细（只计基准日及以前，期后收款不得提前冲减） | 不符 |
| 余额与方向 | 未收 == 应收 − 已收；多收形成贷方余额单列，不抵应收、不计提 | 不符 / 单列 |
| 唯一性 | 同客户 + 开票日期 + 金额只开一次；收款必须对应存在的发票 | 不符 |
| 计提率表 | 六档账龄计提率单调不减、在 0–100% 内 | 不符 |
| 计提 ⭐ | 单项计提客户按单项比例，其余按账龄组合；应计提 vs 账面坏账准备 → 补提/冲回 | 需补提 / 冲回 |
| 对总账 | 应收台账合计 == 1122 总账 | 不符 |
| 守恒 | Σ各段 == 核实应收；Σ计提 == Σ(段余额×段率) + Σ单项 | 自检 |

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(应收+收款目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式、白名单、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 净额掩盖 | 守恒 | 正负成对错误相互抵消，净差为0但双向各错（如银行多记100+企业多记100） | 分向列示+分向限额；加「笔数守恒」配合金额守恒 | 🟢可自补 |
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |

> **已接入** `scripts/ar_aging_baddebt_v2.py`：到期日按信用期独立推算、已收对收款明细（含期后收款截断）、多收单列、重复开票与无发票收款、计提率单调校验、单项优先+六档组合矩阵、应计提对账面坏账准备、应收对总账。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☑ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☐ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

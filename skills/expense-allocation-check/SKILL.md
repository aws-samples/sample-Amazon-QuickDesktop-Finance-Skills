# 期间费用分摊复核

## Overview
对待摊费用台账的分摊逻辑做合规校验——每笔待摊费用按分摊月数均匀摊销。核心验收判据是**分摊守恒 + 账面恒等式**：月摊额×分摊月数=原值、账面余额=原值−累计摊销，叠加累计摊销一致性、超摊与负值边界检测，确保期间费用分摊准确、账面余额真实。

## 数据敏感性
费用数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始费用数据，只看结果摘要；分摊校验在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **分摊守恒** ⭐ | 月摊额 × 分摊月数 == 原值 | 不等 → fail |
| **账面恒等式** ⭐ | 账面余额 == 原值 − 累计摊销 | 不等 → fail |
| **累计一致** | 累计摊销 == 月摊额 × 已摊期数 | 不等 → fail |
| **边界（超摊）** | 已摊期数 ≤ 分摊月数 | 超 → fail |
| **边界（负值）** | 账面余额 ≥ 0 | 负 → fail |
| **期间推算** ⭐ | 已摊期数由「起始月 → `{{period_end}}`」独立推算，不采信台账自报值 | 不符 → fail |
| **期限白名单** | 分摊月数 ≤ 费用类别最长月数 | 超 → fail |
| **本期入账一致** ⭐ | 台账本期应摊 == 总账本期入账；入账科目 ∈ 部门允许科目 | 不符 / 漏入账 → fail |
| **范围完备** | 总账有摊销而台账无此单；台账已摊完而总账仍入账 | 有 → fail |

## Lessons Learned
### Do
- 分摊守恒（月摊×月数=原值）是分摊基础，错了会累积到每期损益。
- 账面恒等式（账面=原值−累计）逐笔自洽，是账实一致的核心。
- 超摊与负值必须硬拦截，防止费用摊完仍入账、虚增费用。

### Don't
- 不要放行分摊不守恒的记录——分摊基础错误无法靠后期调整弥补。
- 不要忽略超摊——已摊期数超过分摊月数会持续虚增费用。

### Common Failures
- 月摊额有四舍五入误差：守恒容差按 max(0.5, 分摊月数 × 0.01) 放宽，即逐月四舍五入到分产生的累计误差上限，避免尾差误报。
- 台账无月摊额列：由 原值÷分摊月数 推算后再校验。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 分摊方法（直线法/其他）、尾差处理口径、基准期按会计政策确认。
- 是否将折旧、无形资产摊销一并纳入（同一判据可复用）需确认范围。

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(待摊台账+总账目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 净额掩盖 | 守恒 | 正负成对错误相互抵消，净差为0但双向各错（如银行多记100+企业多记100） | 分向列示+分向限额；加「笔数守恒」配合金额守恒 | 🟢可自补 |
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |

> **已接入** `scripts/expense_allocation_v2.py`：已摊期数由起始月独立推算、费用类别期限白名单、部门×科目交叉白名单、台账↔总账本期入账双向比对（漏入账、台账外摊销、摊完仍入账）、入账差异归因。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

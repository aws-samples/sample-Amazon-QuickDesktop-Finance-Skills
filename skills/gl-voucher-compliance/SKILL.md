# 总账凭证合规自检

## Overview
在凭证过账前，自动校验每张记账凭证是否合规——借贷是否平衡、科目是否在启用白名单内、会计期间是否合法、摘要是否完整、大额凭证是否有附件。核心验收判据是**白名单**（正向清单，启用即合法）。替代人工逐张翻凭证。

## 数据敏感性
总账数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。SAP 无内置连接器，须走 MCP（sap-cli --mcp）。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **白名单** ⭐ | 科目 ∈ 启用科目表 | 否 → fail |
| **白名单** ⭐ | 会计期间 ∈ 合法期间 | 否 → fail |
| **交叉白名单** ⭐ | 业务类型 × 借/贷方向 × 允许科目 | 科目合法但与业务不符 → fail |
| **恒等式** | Σ借方 == Σ贷方（容差0.01）| 否 → fail |
| **完整性** | 分录数≥2、摘要非空 | 否 → fail/review |
| **边界** | 金额>5万须有附件 | 否 → review |
| **守恒（自检）** | Σ状态数 == 总凭证数；Σ各凭证分录数 == 输入行数；全表借贷差 == 不平凭证差额合计 | 否 → 分析错误 |

## Workflow

### Step 1: 加载安全契约
- **Mode**: `deterministic`
- **Tool**: `load_skill`；随后按 financial-local-safety Step 1 用 `folder_list`、`list_outposts` 做前置校验
- **Input**: 无
- **Output**: 已加载 financial-local-safety

### Step 2: 读取凭证与白名单
- **Mode**: `agentic`
- **Input**: `{{entries_path}}`, `{{whitelist_path}}`, `{{rules_path}}`
- **Output**: 分录记录 + 科目白名单集合 + 业务类型交叉白名单
- **Validate**: 两表非空，关键字段存在
- **On failure**: 字段名不符时提示核对；合法会计期间需在脚本 `VALID_PERIODS` 参数化或提示用户配置。

### Step 3: 执行合规校验
- **Mode**: `deterministic`
- **Tool**: `run_python_on_device`（计算只在设备端进行，见 financial-local-safety 铁律 2）
- **Input**: 三个路径，调用 `scripts/gl_voucher_check_v2.py` 的 `check(entries, whitelist, rules, valid_periods)`
- **Output**: 逐凭证结果（借贷合计/差额/问题标签）+ 汇总（合规率、问题类型、不合规金额、制单人风险、守恒自检）+ 输入文件 SHA-256 指纹与时间戳（可回溯）
- **Validate**: 守恒 assert 通过

### Step 4: 生成讲解页/仪表盘（可选）
- **Mode**: `agentic`
- **Tool**: `run_python_on_device_with_write`（写入授权本地目录）
- **Input**: Step 3 的分析 JSON
- **Output**: 纯 SVG/CSS 自讲解 HTML（甜甜圈/问题类型条/制单人风险/不合规清单 + TTS 控制栏）

### Step 5: 归档
- **Mode**: `deterministic`
- **Tool**: `file_copy`
- **Output**: 存入 `agent_files/artifacts/finance_scenarios/04_gl_voucher/`

## Output
- 数据质量：`data_issues` 列出无法解析或不应留空却留空的数值单元格（文件、行号、字段、原值），该行不参与计算、不按 0 计；`all_ok` 为总判定，有任何数据质量问题或问题标签时为 `False`
- 输出与留痕：命令行 `python scripts/gl_voucher_check_v2.py <gl_entries.csv> <account_whitelist.csv> [business_rules.csv] [结果文件名.json] [--out-dir <授权本地输出目录>]`；结果只写入 `--out-dir`，未给出时为当前目录下 `finance_outputs/`（默认文件名 `analysis.json`）；结果文件名只能是该目录内的 `.json` 文件名，含 `..`、子目录、目录外绝对路径或目标为符号链接时一律拒绝并以退出码 2 结束，未知选项同样退出码 2；文件权限 0600；stdout 只回一行状态（总判定、条数、数据质量问题数、问题标签类数、结果文件与审计日志路径），不回金额与明细；每次写出在同目录 `audit_log.jsonl` 追加一条记录（时间、操作者、引擎及其 SHA-256、非路径参数、输入文件 SHA-256、结果哈希、上一条记录哈希），不含明细与个人信息；直接调用函数不写文件也不记日志，需要归档的结果必须走命令行入口

- 可选：自讲解 HTML 仪表盘

## Lessons Learned
### Do
- 用白名单（正向清单）而非黑名单——只放行明确允许的科目/期间，天然封闭。
- 借贷不平、科目越权、非法期间为硬错误(fail)；缺摘要、大额缺附件为瑕疵(review)可补正。
- 合法会计期间应参数化，随财务启用状态更新。

### Don't
- 不要用黑名单反向排除违规科目——新增违规项会漏网。
- 不要放行借贷不平的凭证——恒等式是会计铁律，一票否决。

### Common Failures
- 分录按凭证号归集时，表头字段（借方/贷方/科目）名称须与脚本一致。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 合法会计期间范围、大额附件阈值（默认5万）按客户口径确认。
- 科目白名单来源（ERP 导出或手工维护）需确认更新机制。

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(凭证, 科目白名单, 业务规则)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**恒等式、白名单** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 合法但不适用 | 白名单 | 值在白名单内但用错场景（如6%与13%都合法，用错税率照样过） | 单字段白名单→交叉白名单（业务类型×允许值）；白名单版本化+生效日 | 🟢可自补 |

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☐ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」

> **已接入** `scripts/gl_voucher_check_v2.py`：业务类型 × 借/贷方向 × 允许科目三元校验；样例中 6 张「科目合法但与业务不符」的凭证全部抓出。
- ☐ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

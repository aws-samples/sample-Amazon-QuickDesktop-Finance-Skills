# 供应商对账

## Overview
在付款或期末结账前，将本方应付台账与供应商寄来的对账单双向勾稽——逐笔匹配单据，识别金额不符、单方挂账（本方缺/供方缺）、时间性差异，并将双方余额差额完整拆解归因。核心验收判据是**交叉一致 + 差异归因**：不仅找出差异，更要证明"差额闭合"（每一分差额都有出处）。

## 数据敏感性
往来数据含供应商商业信息。**执行前先加载 `financial-local-safety` skill**，本地模式处理。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **交叉一致** ⭐ | 同单据号双方金额一致（容差0.01）| 不等 → difference |
| **完整性** | 每单据双方都有记录 | 单方缺 → exception |
| **时间性** | 双方日期差 ≤ 阈值（默认5天）| 超阈 → 时间性差异 |
| **差异归因** ⭐ | 余额差额 == 供方独有 − 我方独有 + 金额不符净差 | 不闭合 → 归因遗漏 |
| **守恒（自检）** | Σ状态数 == 总单据数 | 不等 → 分析错误 |

## Lessons Learned
### Do
- 差额必须完整归因并做闭合 assert——归因之和精确等于余额差额，才算对账完成。
- 时间性差异（跨期）与永久性差异（金额错、漏记）分开——前者会自动消化。
- 单方挂账判 exception 须人工核实，不可自动调账。

### Don't
- 不要只报告"有差异"就结束——未闭合的差额等于对账没做完。
- 不要用发票日期以外的口径混算时点，导致时间性差异误判。

### Common Failures
- 差额闭合 assert 失败：通常是漏了某类差异（如一方有多条同单据号），检查归因分解。
- 供应商对账单是 PDF：先解析为结构化 CSV 再进脚本。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 时间性差异阈值（默认5天）、单据号匹配键（是否含行号）按客户口径确认。
- 供应商对账单格式（PDF/Excel/EDI）确认后再定解析方式。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 范围完备 | 本方有余额的供应商必须回函 | 未回函单列 |
| 期初一致 | 本方期初 == 供方期初 | 不一致 |
| 余额恒等式 ⭐ | 本方：期初+Σ明细==余额表期末；供方：期初+增加−减少==自报期末，且与明细一致 | 不符 |
| 逐笔匹配 | 供应商 + 归一化单据号；同一方同号多次 → 重复入账 | 异常 |
| 余额唯一 | 本方余额表、供方对账单汇总中同一供应商编码只能有一行；重复时保留首行，并记「本方余额表重复」「供方汇总重复」 | 异常 |
| 单号纠错 | 未匹配项同供应商、同金额、日期差 ≤3 天 → 疑似单号录错 | 待核实 |
| 交叉一致 | 金额相反 → 方向错误；金额不等 → 金额不符；类型不同 → 类型不一致 | 异常 / 差异 |
| 时间性 | 截止日前 5 天内的单边项 → 在途（下期核销） | 在途 |
| 差额闭合 ⭐ | 供方期末−本方期末 = 期初差+供方独有−本方独有+配对金额差+供方汇总差−本方余额表差；另列正/负向毛额 | 自检 |

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(本方台账+供应商对账单目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**差异归因、恒等式、交叉一致、唯一性** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 同源错误 | 交叉一致 | 两个「独立」来源实际同源，一起错则互证成功 | 标注每个来源的真实独立性；关键项引外部锚点（工商/银行/金税/合同） | 🟡需外部锚点 |
| 范围盲区 | 交叉一致 | 只核对「已进入两表」的记录，单边未登记项不进对比 | 双向名单比对：A有B无 / B有A无 分别列示 | 🟢可自补 |
| 净额掩盖 | 差异归因 | 归因基于净差，成对反向错误在净额层面消失 | 分向（正/负）分别归因并设分向限额 | 🟢可自补 |
| **单向检查漏反向** ⚠️ | 场景特有 | 只查一个方向（如只查少缴/只查我方缺），反向错误（多缴/对方缺）漏检 | 双向列示：正差与负差、A单边与B单边分别输出 | 🟢可自补 |

> **已接入** `scripts/supplier_recon_v2.py`：未回函范围、期初与双方余额恒等式、归一化单号与单号纠错、重复入账、方向/类型、在途识别、逐供应商差额闭合与分向毛额。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☑ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☐ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☑ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

# 应付账龄分析

## Overview
按账龄将应付账款分桶（未到期 / 1-30 / 31-60 / 61-90 / 90天以上），量化逾期金额与占比，识别欠款集中的供应商，为付款计划与现金流安排提供依据。核心验收判据是**分桶守恒**（各桶合计必等于核实后的未付余额，MECE 互斥且完备），前提是每笔余额与到期日先核实：到期日按主数据账期独立推算、已付对付款明细、合计对总账。

## 数据敏感性
应付/供应商数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **分桶守恒** ⭐ | Σ各账龄桶金额 == 核实贷方余额 | 不等 → 分桶逻辑错误 |
| **恒等式** | 未付 == 应付 − 已付 | 不等 → 数据错误 |
| **边界** | 逾期天数 = 基准日 − 推算到期日 | ≤0 → 未到期 |
| **完整性** | 每条未付记录必属且仅属一个桶 | 重复/遗漏 → 错误 |

## Workflow

### Step 1: 加载安全契约
- **Mode**: `deterministic`
- **Tool**: `load_skill`；随后按 financial-local-safety Step 1 用 `folder_list`、`list_outposts` 做前置校验
- **Input**: 无
- **Output**: 已加载 financial-local-safety

### Step 2: 读取应付数据
- **Mode**: `agentic`
- **Input**: `{{data_dir}}`, `{{base_date}}`
- **Output**: 应付台账、付款明细、供应商主数据、总账余额
- **Validate**: 四个文件存在，关键字段齐全
- **On failure**: 字段名不符时提示核对表头；基准日缺省时使用默认值并在报告中声明。

### Step 3: 核实余额并分桶
- **Mode**: `deterministic`
- **Tool**: `run_python_on_device`（计算只在设备端进行，见 financial-local-safety 铁律 2）
- **Input**: 调用 `scripts/ap_aging_v2.py` 的 `check(data_dir, base_date)`
- **Output**: 逐单结果（推算到期日、账龄天数、明细已付、核实未付、问题标签）+ 五桶金额/笔数 + 逾期率 + 借方余额 + 无应付付款 + 供应商排名 + 未来 30 天到期额 + 台账与总账差 + 输入指纹与时间戳
- **Validate**: 笔数守恒与分桶守恒 assert 通过

### Step 4: 生成讲解页/报告（可选）
- **Mode**: `agentic`
- **Tool**: `run_python_on_device_with_write`（写入授权本地目录）
- **Input**: Step 3 的分析 JSON
- **Output**: 纯 SVG/CSS 自讲解 HTML + 网页/PDF/Markdown/Excel 报告

### Step 5: 归档
- **Mode**: `deterministic`
- **Tool**: `file_copy`
- **Input**: 报告与证据文件
- **Output**: 存入 `agent_files/artifacts/finance_scenarios/10_ap_aging/`

- 逾期供应商排名、未来 30 天到期额（付款计划）
- 台账与总账差异、证据 JSON

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 主数据 | 供应商已登记；台账账期 == 主数据账期 | 不符 |
| 到期日推算 ⭐ | 到期日 == 发票日期 + 主数据账期（不采信台账到期日） | 不符 |
| 已付核实 ⭐ | 台账已付 == Σ付款明细（截至基准日）；未付 == 应付 − 已付 | 不符 |
| 付款对象 ⭐ | 付款的供应商编码 == 应付单的供应商编码；不一致的付款不冲减该应付 | 不符 |
| 唯一性 | 同供应商 + 发票日期 + 金额只入账一次；同一应付单不重复付款 | 不符 |
| 分向列示 | 只对贷方余额分桶；多付形成的借方余额单列，不抵欠款 | 单列 |
| 对总账 ⭐ | 台账未付合计 == 总账余额、核实未付合计 == 总账余额（不符分别记「应付台账与总账不符」「核实未付与总账不符」，列入 `gl_issues` 并计入 `all_ok`）；付款必须对应存在的应付单 | 不符 |
| 分桶守恒 | Σ各桶 == 核实贷方余额；笔数守恒 | 自检 |

## 样本数据（演示 · 全部虚构）
示例集团（虚构）12 家虚构供应商（账期 15–90 天），209 张应付、148 笔付款，基准日 2026-09-30。
- `samples/clean/`：台账、付款明细、总账三者一致；未付 2,412 万，逾期率 64.9%
- `samples/error/`：植入 12 处错误（到期日推后藏逾期、账期改长、台账已付无付款、未付少记、重复入账、重复付款、无应付付款、供应商未登记、多付负余额、总账未同步、付款对象与应付供应商不一致、付款金额写成千分位无法解析），全部命中、无误报

## Lessons Learned
### Do
- 账龄必须用到期日（发票日 + 主数据账期）计算，并独立推算，不采信台账到期日。
- 已付金额以付款明细为准，未付合计与总账核对。
- 借方余额单列，不与同一供应商欠款相抵。
- 基准日显式给出，保证结果可复现。

### Don't
- 不要用发票日期算账龄——账期内的正常欠款会被误判逾期。
- 不要默认取“今天”为基准日——同一份数据换一天结果就变。
- 不要漏掉守恒校验——分桶遗漏或重复会导致总额对不上。

### Common Failures
- 日期格式非 `YYYY-MM-DD`：需先标准化日期列。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 账龄桶边界（默认 30/60/90）、基准日按客户口径确认。
- 是否将预付、质保金等特殊往来纳入账龄，需确认业务范围。


## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(应付台账,总账,付款,供应商主数据)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式、交叉一致、唯一性** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 净额掩盖 | 守恒 | 多付的借方余额与欠款相抵 | 分向列示，已在脚本中实现 | 🟢已闭合 |
| 到期日被改 | 恒等式 | 台账到期日推后，逾期藏成未到期 | 按主数据账期独立推算，已在脚本中实现 | 🟢已闭合 |
| 账期主数据本身错 | 交叉一致 | 主数据账期与合同不符 | 对接采购合同付款条款 | 🟡需外部锚点 |
| 欠款是否被供应商认可 | 交叉一致 | 台账与总账一致但供应商不认 | 与供应商对账单核对（#11 供应商对账） | 🟡需外部锚点 |

> **已接入** `scripts/ap_aging_v2.py`：到期日按主数据账期独立推算、已付与付款明细核实、付款对象与应付供应商比对、借贷方分向列示、重复入账与重复付款、无应付付款、台账与总账核对、基准日显式化。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☑ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☐ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☑ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

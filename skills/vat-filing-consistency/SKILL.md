# 增值税申报一致性

## Overview
在增值税申报提交前，将申报表各栏次与账载发票汇总逐栏交叉核对，并验证申报表内「本期应纳税额=销项税额−进项税额−上期留抵」恒等式自洽。核心验收判据是**交叉一致 + 恒等式**，识别账表不符与表内计算错误，避免申报差错引发稽查风险。账载汇总承接增值税进销项匹配 skill 的输出。

## 数据敏感性
涉税数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始涉税数据，只看结果摘要；账表核对在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **交叉一致** ⭐ | 申报各栏 == 账载汇总 | 不等 → 账表不符 |
| **恒等式自洽** ⭐ | 应纳税额 == 销项 − 进项 − 上期留抵 | 不等 → 表内计算错误 |
| **完整性** | 申报表栏次齐全 | 缺栏 → 申报不完整 |
| **勾稽** | 税额与金额×税率吻合（承接进销项匹配）| — |

## Lessons Learned
### Do
- 账载是申报的唯一依据——账表不符须查明原因后修正申报表。
- 既查账表交叉一致，也查申报表内恒等式自洽，两道判据缺一不可。
- 上期留抵须与上期申报表期末留抵衔接。

### Don't
- 不要提交账表不符或恒等式不自洽的申报表——会被系统/稽查驳回。
- 不要凭空填报或估填栏次——所有数字回账载。

### Common Failures
- 栏次命名不统一（销项税额/销项税）：读入后映射到标准栏次。
- 申报表缺本期应纳税额列：恒等式无法自洽校验，需补齐。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 上期留抵来源、申报口径（一般纳税人/小规模）确认。
- 是否需将附加税、免抵退等特殊栏次纳入核对范围。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 账表交叉一致 ⭐ | 主表各栏（销项/进项/上期留抵等）== 账载对应项目 | 不符 |
| 附表一恒等式 | 每档 销项税额 == 销售额 × 税率；税率 ∈ 白名单 | 不符 |
| 附表↔主表 | 附表一销项税额合计 == 主表销项税额；附表二税额合计 == 主表进项税额 | 不符 |
| 主表内部恒等式 ⭐ | 应抵扣合计 = 进项−转出+留抵；实际抵扣 = min(应抵扣,销项)；应纳 = 销项−实际抵扣；期末留抵 = 应抵扣−实际抵扣 | 不符 |
| 逻辑互斥 | 应纳税额 与 期末留抵税额 不同时为正 | 冲突 |

## 样本数据（演示 · 全部虚构）
示例集团（虚构）2026-09 申报，账载承接 #15：主表 9 栏 + 附表一（13%/6% 销项）+ 附表二（进项明细）。
- `samples/clean/`：14 项校验全部一致，申报应纳 = 正确应纳 98.25 万

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(账载+申报表目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**恒等式、白名单、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 同源错误 | 交叉一致 | 两个「独立」来源实际同源，一起错则互证成功 | 标注每个来源的真实独立性；关键项引外部锚点（工商/银行/金税/合同） | 🟡需外部锚点 |
| 范围盲区 | 交叉一致 | 只核对「已进入两表」的记录，单边未登记项不进对比 | 双向名单比对：A有B无 / B有A无 分别列示 | 🟢可自补 |
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |

> **已接入** `scripts/vat_filing_check_v2.py`：账表交叉、附表一恒等式与税率白名单、附表↔主表勾稽、主表内部四项恒等式、应纳与留抵逻辑互斥；账载承接 #15 形成端到端链。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☐ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

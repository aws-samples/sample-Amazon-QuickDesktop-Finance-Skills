# 固定资产卡片与实物核对

## Overview
将固定资产账面卡片与实物盘点结果做账实交叉核对——识别有账无物（盘亏）、有物无账（盘盈）、存放位置/使用部门不符，并校验每张卡片的折旧恒等式（账面净值=原值−累计折旧、累计折旧≤原值−残值）。核心验收判据是**交叉一致 + 恒等式**，确保账实相符、资产价值真实。

## 数据敏感性
资产数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始资产数据，只看结果摘要；账实核对在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **交叉一致** ⭐ | 卡片 ↔ 实物一一对应 | 缺一方 → 盘亏/盘盈 exception |
| **折旧恒等式** ⭐ | 账面净值 == 原值 − 累计折旧 | 不等 → difference |
| **位置部门一致** | 卡片部门/地点 == 实物 | 不符 → difference |
| **折旧边界** | 累计折旧 ≤ 原值 − 残值 | 超 → exception |

## Lessons Learned
### Do
- 账实交叉取卡片与实物的并集，缺一方即盘亏或盘盈。
- 折旧恒等式（净值=原值−累计折旧）+ 折旧边界（累计≤原值−残值）双校验。
- 盘亏查去向（报废/丢失/调拨未登记）、盘盈补建卡片，位置不符更新台账。

### Don't
- 不要对盘亏直接冲销——须查明去向后规范账务处理。
- 不要遗漏盘盈入账——有物无账须补建卡片。

### Common Failures
- 实物盘点无卡片编号（仅名称/条码）：需先建立编号映射再核对。
- 残值率影响折旧边界：默认按原值上限，精细化时用 原值−残值。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 残值率、折旧方法（直线/加速）确认，用于折旧边界精确校验。
- 盘盈盘亏的账务处理口径（营业外收支/前期差错）按会计政策确认。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 账实交叉 ⭐ | 有账无物→盘亏；有物无账→盘盈；部门/位置不符 | 异常 / 差异 |
| 折旧恒等式 | 账面净值 == 原值 − 累计折旧 | 差异 |
| 折旧重算 ⭐ | 月折旧==原值×(1−残值率)/年限；应计提月数按基准日−入账日推算；累计折旧重算 | 差异 |
| 边界 | 累计折旧 ≤ 可折旧总额；净值 ≥ 残值 | 异常 |
| 类别白名单 | 使用年限 ≥ 类别最低；残值率 == 类别规则 | 差异 |
| 状态 | 已处置资产净值应为 0，且不应在盘点表 | 异常 |
| 守恒 | Σ原值、累计、净值；净值 = 原值 − 累计 | 自检 |
| 参数来源 ⭐ | 应计提月数按调用方给出的盘点基准日推算；params.csv 中的盘点基准日只比对，不同记「盘点基准日与核对口径不一致」（`param_issues`，计入 `all_ok`） | 参数问题 |
| 唯一性 | 卡片与盘点记录中同一卡片编号只能有一行；重复时保留首行参与比对，并记「重复卡片」「重复盘点记录」（`duplicate_keys`） | 异常 |

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(资产卡片+盘点目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**恒等式、白名单、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 同源错误 | 交叉一致 | 两个「独立」来源实际同源，一起错则互证成功 | 标注每个来源的真实独立性；关键项引外部锚点（工商/银行/金税/合同） | 🟡需外部锚点 |
| 范围盲区 | 交叉一致 | 只核对「已进入两表」的记录，单边未登记项不进对比 | 双向名单比对：A有B无 / B有A无 分别列示 | 🟢可自补 |
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |
| **未登记资产盲区** ⚠️ | 场景特有 | 未登记入卡的实物资产不在账面，账实核对对其永远全绿 | 实物盘点清单 vs 资产卡片双向比对（有卡无物/有物无卡） | 🟢可自补 |

> **已接入** `scripts/fixed_asset_check_v2.py`：账实交叉（盘亏/盘盈/部门位置）、折旧恒等式与直线法重算、累计折旧与净值边界、类别使用年限与残值率白名单、已处置资产状态、原值/累计/净值守恒。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☐ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☑ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

# 报表勾稽自检 Skill

## Overview

报表勾稽自检技能。在财务报表对外报出前，自动校验三大报表（资产负债表/利润表/现金流量表）+ 未分配利润滚动表的全部勾稽关系——会计恒等式、各表内部小计、三表间跨表勾稽，一次性抓出所有不平。核心判据为**恒等式**，适用于月末/季末/年末报表编制完成后、对外报送前的自检环节。

交付物有两层：给机器/复核用的**结果 JSON** + 一行摘要，以及给财务归档备查用的**可归档勾稽核对底稿（HTML）**——带索引号、数据来源、输入指纹、逐项核对、结论与处理意见、签字栏，结论随校验结果（全平/不平）自动切换。

## Workflow

### Step 1: 读取四表
- **Mode**: `deterministic`
- **Tool**: `run_python`
- **Input**: 用户当期的 balance_sheet.csv / income_statement.csv / cash_flow.csv / retained_earnings.csv（各含「项目,金额[,分区]」列）——**路径必须由调用者显式提供**，脚本不设默认路径
- **Output**: 四个键值化 dict + 四表列示数据（供底稿渲染）
- **Validate**: 四表均成功载入且含必需科目（脚本按 `REQUIRED` 校验：必需项目缺失、金额无法解析或留空 → 登记 `data_issues`，引用它的勾稽项判不通过，`all_tie=False`，不按 0 计）
- **On failure**: 提示缺失的表或科目

### Step 2: 执行勾稽校验
- **Mode**: `deterministic`
- **Tool**: `run_python` → `check_report_tieout(bs_path, inc_path, cf_path, re_path, tol=0)`（scripts/report_tieout_check_v2.py）
- **Input**: Step 1 的四表路径（四个参数全必填，无默认值）；`tol` 为差异容差（元），0 或不传时取默认 0.5，只能在 (0, 1.0] 内，超出抛 `ValueError`；容差逐次传入，不改写模块全局，不影响之后的调用
- **Output**: 勾稽校验结果（表内小计 + 会计恒等式 + 三表勾稽），每项含勾稽项/类型/左值/右值/差异/是否通过，附 ISO8601 时间戳；结果的 `tol` 字段披露本次实际采用的容差
- **Validate**: 独立自检——通过数 + 不平数 == 总校验数
- **On failure**: assert 触发说明分析逻辑错误

### Step 3: 输出结果 JSON + 摘要
- **Mode**: `deterministic`
- **Tool**: `run_python_with_write`（结果 JSON 落盘）
- **Input**: Step 2 的校验结果
- **Output**: 结果 JSON 落盘（逐项校验 + 不平明细 + 状态 all_tie）+ 一行 stdout 摘要
- **Validate**: 结果 JSON 落盘成功
- **On failure**: 逐项打印，确保至少输出校验清单
- **输出与留痕**：命令行 `python scripts/report_tieout_check_v2.py <balance_sheet.csv> <income_statement.csv> <cash_flow.csv> <retained_earnings.csv> [结果文件名.json] [--tol 容差] [--out-dir <授权本地输出目录>]`；结果只写入 `--out-dir`，未给出时为当前目录下 `finance_outputs/`（默认文件名 `analysis.json`）；结果文件名只能是该目录内的 `.json` 文件名，含 `..`、子目录、目录外绝对路径或目标为符号链接时一律拒绝并以退出码 2 结束，`--tol` 越界或未知选项同样退出码 2；文件权限 0600；stdout 只回一行状态（全平与否、条数、数据质量问题数、问题标签类数、结果文件与审计日志路径）；每次写出在同目录 `audit_log.jsonl` 追加一条记录（时间、操作者、引擎及其 SHA-256、实际容差、四表文件 SHA-256、结果哈希、上一条记录哈希），不含明细

### Step 4: 渲染可归档勾稽底稿（HTML）
- **Mode**: `deterministic`
- **Tool**: `run_python_with_write` → `render_tieout_worksheet(result, table_data, meta, out_path, out_dir, input_paths)`（scripts/render_worksheet.py，底稿 HTML 落盘：`out_path` 只能是 `out_dir` 内的 `.html`/`.htm` 文件名，`out_dir` 未给出时为当前目录下 `finance_outputs/`，越界或符号链接抛 `OutputPathError`；文件 0600，并向同目录 `audit_log.jsonl` 追加一条记录；`input_paths` 传入四表 CSV 路径（键 bs/inc/cf/re）时记录含四表完整 SHA-256，未传入时该记录不含输入哈希；底稿逐项核对表下方的核对口径注明结果中的实际容差）
- **Input**: Step 2 的校验结果 `result` + Step 1 的四表列示数据 `table_data`（键 bs/inc/cf/re）+ 可选 `meta`（index 索引号 / as_of 时点 / fingerprint 输入指纹 SHA-256 / entity 主体 / basis 准则）
- **Output**: 可归档底稿 HTML——抬头（索引号/主体/时点/准则/数据来源/输入指纹/核对方法/核对时间）+ 四表列示 + 逐项核对表 + 结论与处理意见（全平→"具备对外报出条件"绿；不平→"不具备对外报出条件"红并列不符项）+ 已知盲区声明 + 签字栏（编制/复核/财务负责人/归档索引）
- **Validate**: 结论区与 all_tie 一致（全平出绿、不平出红并逐条列不符项）
- **On failure**: 回退到 Step 3 的 JSON，提示底稿渲染失败但校验结果有效

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期四表**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check_report_tieout(四表路径)` | `python scripts/self_check.py` |
| 目的 | 核对这套真实报表平不平、可否报出 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 脚本函数**不设指向 samples 的默认路径**——`check_report_tieout` 四参数全必填。调用者给什么就核什么，绝不会在用户漏传时默默去核样本、假报"全平通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"。正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应得 17/17 全平、对 `samples/error/` 应正好抓出 8 条不平（其中 2 条因投资收益、其他综合收益金额无法解析标为缺数据，缺数据须挂在引用该项目的勾稽项上），并渲染底稿核对结论为「不具备对外报出条件」，与 `samples/expected.json` 黄金答案比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——它有确定的已知错误数和期望抓取数，脚本一旦退化立刻暴露，比"全平版全过"更有鉴别力。

## 目标
在财务报表对外报出前，自动校验三大报表的全部勾稽关系——资产负债表会计恒等式（资产=负债+所有者权益）、各表内部小计、以及三表之间的勾稽（现金流量表期末现金=资产负债表货币资金、利润表净利润=未分配利润滚动增量等），一次性抓出所有不平，并产出可归档的勾稽核对底稿。

## 上层（业务逻辑层 · 不折旧 · 跨平台）

### 输入契约
| 表 | 必填字段 |
|----|---------|
| **资产负债表 balance_sheet** | 项目, 金额（含各资产/负债/权益科目及小计）|
| **利润表 income_statement** | 项目, 金额（收入/成本/费用/利润总额/所得税/净利润）|
| **现金流量表 cash_flow** | 项目, 金额（经营/投资/筹资净额/净增加/期初/期末）|
| **未分配利润滚动 retained_earnings** | 项目, 金额（期初/本期净利润/期末）|

### 处理步骤
1. **读取四表** — 键值化载入，并保留四表列示数据供底稿渲染。
2. **表内小计校验** — 各报表内部合计=明细之和。
3. **会计恒等式** — 资产总计 == 负债合计 + 所有者权益合计。
4. **三表间勾稽** — CF期末现金=BS货币资金；利润表净利润=滚动表净利润；BS未分配利润=滚动表期末。
5. **独立自检** — 通过数+不平数=总校验数。
6. **输出结果 JSON + 摘要**。
7. **渲染可归档底稿 HTML** — 调 `render_tieout_worksheet()`。

### 输出契约
两层交付：
- **结果 JSON + 摘要**（给机器/复核）：逐项勾稽（勾稽项、类型、左值、右值、差异、是否通过）+ 通过率 + 不平处数 + 不平明细 + 状态（all_tie 全平可报出 / 有不平须修正）+ 时间戳。
- **可归档勾稽核对底稿 HTML**（给财务归档备查）：索引号 + 主体/时点/准则/货币单位 + 数据来源 + 输入指纹 SHA-256 + 核对方法/时间 + 四表数据列示 + 勾稽逐项核对表 + 结论与处理意见（随结果自动切换绿/红）+ 已知盲区声明 + 编制/复核/财务负责人/归档索引签字栏。

> 底稿 ≠ 验收报告。底稿只用**当期单套真实数据**（不含植错版对照），面向财务归档；验收/演示报告才用 clean+error 两版对照证明脚本可信——两者分开，不要混在同一产物里。

### 验收判据（核心：恒等式）
| 判据 | 规则 | 触发 |
|------|------|------|
| **会计恒等式** ⭐ | 资产 == 负债 + 所有者权益 | 不等 → 不平 |
| **表内小计** ⭐ | 合计 == 明细之和（各表）| 不等 → 不平 |
| **三表勾稽** ⭐ | 跨表同源数据一致 | 不等 → 不平 |
| **独立自检** | 通过数+不平数 == 总校验数 | 不等 → 分析错误 |

### 禁止规则
- 任一勾稽不平的报表不得对外报出——必须先查明差异来源修正。
- 一处错误常连锁触发多条勾稽告警（表内+跨表），须追根溯源而非逐条掩盖。
- 三表勾稽不能只做表内平衡——跨表一致才是财报真实性的关键。
- 底稿不得混入植错版对照数据——底稿是业务归档件，只核当期真实那一套。
- 正式运行不得读取 samples/ 夹具——样本只供 self_check.py 回归用。

## 下层（平台适配层 · 可替换）
- 数据获取：本地报表 CSV；或财务系统/合并报表导出。
- 计算：`scripts/report_tieout_check_v2.py`（确定性校验）。
- 底稿渲染：`scripts/render_worksheet.py`（`render_tieout_worksheet()`，纯字符串拼装无第三方依赖；如需 PDF 可在设备端用 STHeiti 中文字体打印该 HTML）。

## 样本数据（演示/自检 · 全部虚构）
丰富版报表结构（示例集团，虚构），捆绑于 `samples/`：`balance_sheet.csv`（32行·含流动/非流动分区+多层小计）+ `income_statement.csv`（14行·营业利润/利润总额多层级）+ `cash_flow.csv` + `retained_earnings.csv`（含提取盈余公积+分配股利）。含「分区」列驱动结构化小计校验。
- `samples/clean/`：完全勾稽平（17项校验全绿）
- `samples/error/`：植入5处（资产总计少计42.75万/净利润多计2.5万/期末现金差10万/投资收益写成千分位无法解析/新增其他综合收益写成千分位无法解析，按 0 计时所有者权益合计恰好相符），连锁触发8处告警（其中 2 处为缺数据）
- `samples/expected.json`：黄金答案（clean 17/17 全平；error 9/17、8 处不符及不符项清单、2 处数据质量问题、缺数据所挂的勾稽项）

脚本为**结构驱动**（`report_tieout_check_v2.py`）：按「分区」列动态求和校验各层小计，兼容完整报表结构，也兼容固定科目模式。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、恒等式** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立（如期末现金取错期、子公司混入） | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |
| **同源数据一起错** ⚠️ | 场景特有 | 三表若都由同一错误试算平衡表自动生成，跨表勾稽全绿但源头即错 | 关键项引外部锚点（银行对账单/纳税申报/审计调整）打破同源 | 🟡需外部锚点 |

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（银行/金税/审计）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准，只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

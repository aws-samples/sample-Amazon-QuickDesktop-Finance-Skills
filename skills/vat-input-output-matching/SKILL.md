# 增值税进销项匹配

## Overview
对增值税进项与销项发票做逐张税额校验（税额=金额×税率）、税率合法性校验（白名单），并勾稽本期进销项税额得出应纳税额（销项−进项）。核心验收判据是**税额恒等式 + 税率白名单**，识别税额计算错误、非法税率、阴阳倒挂，为增值税申报提供干净的税额基础。

## 数据敏感性
涉税数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始涉税数据，只看结果摘要；税额校验在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **税额恒等式** ⭐ | 税额 == 金额 × 税率 | 不等 → fail |
| **税率白名单** ⭐ | 税率 ∈ {13%,9%,6%,3%,0%} | 否 → fail |
| **勾稽守恒** | 应纳税额 == 销项 − 进项 | — |
| **边界** | 税额 ≤ 金额（不倒挂）| 倒挂 → fail |

## Lessons Learned
### Do
- 税额恒等式（税额=金额×税率）逐张校验，容差按 max(0.5, 金额×0.1%) 放宽尾差。
- 只有校验通过的发票才计入进销项勾稽，异常票先剔除待核实。
- 应纳税额为负是留抵税额（进项>销项），据实结转下期，非错误。

### Don't
- 不要让税额不符、非法税率的发票进入申报——稽查风险。
- 不要把留抵（负应纳）当成错误——是正常的税务结转。

### Common Failures
- 税率存储格式不一（13 / 0.13 / 13%）：读入后统一归一为小数再校验。
- 免税/零税率发票：税率0%属合法，税额应为0。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 合法税率集是否需按行业调整（如农产品9%、特定服务6%）确认。
- 是否需对接税务查验API核验票面真伪（本skill只校验税额逻辑，不验真伪）。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 税额恒等式 | 税额 == 金额 × 税率（容差 0.06） | 剔除 |
| 税率白名单 | 13% / 9% / 6% / 5% / 3% / 1% / 0 | 剔除 |
| 交叉白名单 ⭐ | 商品服务类别 × 适用税率（运输 9%、技术服务 6% 等） | 剔除 |
| 唯一与状态 | 发票代码号码唯一；作废不计税；红字必须对应存在的蓝字且不超原票；红字对应的蓝字已作废时该红字剔除并记「红字对应蓝字已作废」，不冲减销项 | 剔除 / 不计税 |
| 销项 | 销方为本公司；开票日期在所属期 | 剔除 |
| 进项抵扣 ⭐ | 购方为本公司；已勾选且勾选期间 == 所属期；发票正常；不属于餐饮、集体福利等不得抵扣项 | 剔除 / 不抵扣 |
| 应纳税额 | 销项 − (可抵扣进项 − 进项转出) − 上期留抵；为负即期末留抵 | 计算 |
| 守恒 | 全部销项 = 计入 + 作废 + 剔除；全部进项 = 可抵扣 + 不抵扣 + 剔除；张数守恒 | 自检 |

## 样本数据（演示 · 全部虚构）
示例集团（虚构）2026-09：销项 98 张（含红字 1、作废 1），进项 118 张（货物、运输、现代服务、住宿、餐饮、不动产租赁；含未勾选与不得抵扣项），上期留抵 18.6 万。
- `samples/clean/`：全部正确，应纳税额 150.85 万
- `samples/error/`：植入 13 处（销项税额多写、技术服务按 13%、11% 旧税率、销项跨期、发票重复、红字无蓝字、餐饮进项抵扣、集体福利抵扣、购方抬头错、作废票抵扣、上期已抵扣重复计入、运输按 6%、进项税额写成千分位无法解析），全部命中、无误报；未经校验直接计算的应纳税额多出 9.2 万


## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(进销项发票目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**恒等式、白名单、唯一性** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 口径与时点 | 恒等式 | 等式内部自洽，但取数口径（时点/主体/准则）错，等式照样成立 | 口径三元组声明（时点+主体+准则）；跨期衔接校验（本期期初=上期期末） | 🟢可自补 |
| 合法但不适用 | 白名单 | 值在白名单内但用错场景（如6%与13%都合法，用错税率照样过） | 单字段白名单→交叉白名单（业务类型×允许值）；白名单版本化+生效日 | 🟢可自补 |

> **已接入** `scripts/vat_matching_v2.py`：类别×税率交叉白名单、发票唯一与作废/红字处理、销项所属期、进项抬头/勾选期间/不得抵扣项、上期留抵与进项转出、销项与进项守恒。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

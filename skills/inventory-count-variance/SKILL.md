# 存货盘点差异处理

## Overview
将存货账存台账与实盘结果按 SKU 做账实交叉核对——识别盘亏（账>实）、盘盈（账<实）、账有实无、实有账无，按单价折算差异金额，并做差异守恒归因。核心验收判据是**交叉一致 + 差异守恒**，确保账实相符、存货价值真实。

## 数据敏感性
库存数据敏感。**执行前先加载 `financial-local-safety` skill**，本地模式处理。运行时模型只做编排、不接触原始库存数据，只看结果摘要；账实核对在本地沙箱由确定性脚本完成。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **交叉一致** ⭐ | 账存 ↔ 实盘 SKU 一一对应 | 单边 → exception |
| **差异守恒** ⭐ | 净差异 == Σ盘盈金额 + Σ盘亏金额 | 不等 → 归因遗漏 |
| **数量恒等式** | 差异数量 == 实盘 − 账存 | 不等 → 计算错误 |
| **金额折算** | 差异金额 == 差异数量 × 单价 | 不等 → 折算错误 |

### Step 1: 加载安全契约
- **Mode**: `deterministic`
- **Tool**: `load_skill`；随后按 financial-local-safety Step 1 用 `folder_list`、`list_outposts` 做前置校验
- **Input**: 无
- **Output**: 已加载 financial-local-safety

### Step 2: 读取账存台账与实盘表
- **Mode**: `agentic`
- **Input**: `{{data_dir}}`, `{{data_dir}}`
- **Output**: 账存 + 实盘，按 SKU 索引
- **Validate**: SKU、单价、账存数量、实盘数量字段齐全
- **On failure**: 实盘若为 PDA/扫码导出需先按 SKU 汇总；同 SKU 多仓时按 SKU+仓库联合键。

### Step 3: 执行账实核对与差异归因
- **Mode**: `deterministic`
- **Tool**: `run_python_on_device`（计算只在设备端进行，见 financial-local-safety 铁律 2）
- **Input**: 数据目录，调用 `scripts/inventory_count_check_v2.py` 的 `check(data_dir, major=None, loss_rates=None)`；重大差异金额阈值与合理损耗率取引擎常量（阈值 50000 元；原材料 1%、半成品 0.5%、产成品 0.5%、包装物 2%、低值易耗 3%），或由调用方显式传入 `major`（须为大于 0 的有限数）与 `loss_rates`（按类别覆盖，每项须在 0–5% 内），越界抛 `ValueError`；命令行对应 `--major`、`--loss-rate 类别=比例`
- **Output**: 逐 SKU 核对 + 盘盈盘亏 + 净差异 + 类别分布
- **Validate**: 守恒自检 + 差异守恒 assert 均通过

### Step 4: 生成讲解页/仪表盘（可选）
- **Mode**: `agentic`

- **Validate**: 单屏不溢出、script 花括号配平、无 lookbehind 正则

### Step 5: 归档
- **Mode**: `deterministic`
- **Tool**: `file_copy`

## Lessons Learned
### Do
- 账实交叉取账存与实盘的并集，缺一方即账有实无或实有账无。
- 差异金额按单价折算并做差异守恒（净差异=Σ盘盈+Σ盘亏）。
- 盘亏查因（损耗/被盗/发货未记）、盘盈查来源（多收/退货未记）后账务处理。

### Don't
- 不要直接调平账面掩盖盘亏——须查明原因后规范处理。
- 不要只报数量差不折金额——差异金额才是账务与内控依据。

### Common Failures
- 实有账无无账面单价：差异金额记0，需人工补单价评估。
- 同 SKU 多仓：用 SKU+仓库联合键，避免跨仓误合并。
- 中文表头 BOM：用 `encoding="utf-8-sig"`。

### When to Ask the User
- 盘盈盘亏的账务处理口径（管理费用/营业外收支）、计价方法（加权平均/先进先出）确认。
- 是否按仓库分别核对、是否含在途/委外库存。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 账实交叉 ⭐ | 按 SKU+仓库；账有实无→全盘亏；实有账无→全盘盈；账实均有→比数量 | 异常 / 差异 |
| 单位一致 | 账实单位相同（否则数量不可比） | 异常 |
| 合理损耗 ⭐ | 差异率 ≤ 类别损耗率 → 正常损耗（不计异常）；超出 → 异常盘盈/盘亏 | 差异 |
| 金额分级 | 差异金额 ≥ 重大差异阈值 → 重大差异 | 异常/差异 |
| 参数来源 ⭐ | 阈值与损耗率以引擎常量或调用方参数为准（结果 `params` 披露采用值与来源）；数据目录中的 tolerance_rules.csv、params.csv 只用于比对，类别比例或阈值不同记「合理损耗率与核对口径不一致」「重大差异金额阈值与核对口径不一致」（`param_issues`，计入 `all_ok`） | 参数问题 |
| 唯一性 | 账存与实盘中同一 SKU+仓库只能有一行；重复时保留首行参与比对，并记「重复账存记录」「重复盘点记录」（`duplicate_keys`） | 异常 |
| 边界 | 账存/实盘 ≥ 0；单价 > 0（否则金额无法折算，单列） | 异常 |
| 多仓完整性 | 同一 SKU 所有账存仓位都必须有实盘 | 漏盘 |
| 差异守恒 | 净差异 = 盘盈 − 盘亏；另列盘盈/盘亏毛额 | 自检 |

## 样本数据（演示 · 全部虚构）
示例集团（虚构）59 个 SKU-仓位（原材料/半成品/产成品/包装物/低值易耗，含跨仓 SKU），账面 2.39 亿，各类别设合理损耗率。
- `samples/clean/`：59 项账实相符，其中 10 项差异在损耗率内视为正常损耗
- `samples/error/`：植入 11 处（账有实无、实有账无、盘亏超损耗、盘盈、单位不一致、重大差异、负实盘、多仓漏盘、单价为零、账存为负、实盘数量写成千分位无法解析），全部命中、无误报


## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(账存+实盘目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**守恒、白名单、交叉一致** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 同源错误 | 交叉一致 | 两个「独立」来源实际同源，一起错则互证成功 | 标注每个来源的真实独立性；关键项引外部锚点（工商/银行/金税/合同） | 🟡需外部锚点 |
| 范围盲区 | 交叉一致 | 只核对「已进入两表」的记录，单边未登记项不进对比 | 双向名单比对：A有B无 / B有A无 分别列示 | 🟢可自补 |
| 净额掩盖 | 守恒 | 正负成对错误相互抵消，净差为0但双向各错（如银行多记100+企业多记100） | 分向列示+分向限额；加「笔数守恒」配合金额守恒 | 🟢可自补 |
| **净差掩盖双向差异** ⚠️ | 场景特有 | 大额净差可能掩盖更大的双向差异；计量单位换算错时守恒在错单位下依然成立 | 正负差异分别列示+分向限额；单位换算独立校验 | 🟢可自补 |
| **计量单位换算盲区** ⚠️ | 场景特有 | 换算系数错时，守恒等式在错误单位下依然成立（如吨/公斤混用） | 单位换算系数独立校验；关键物料量纲一致性检查 | 🟢可自补 |

> **已接入** `scripts/inventory_count_check_v2.py`：SKU+仓库账实交叉、单位一致、类别合理损耗率容差、重大差异金额分级、数量非负与单价边界、多仓漏盘完整性、差异守恒与分向毛额。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☑ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☑ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☑ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☐ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误

# 发票查验与重复报销识别

## Overview
在费用报销付款前，对发票台账做多维唯一性核验——识别同一张发票被多次报销、改动发票号但要素相同的"变造重复"、同一报销人的连号发票、以及金额异常。核心验收判据是**唯一性**。这是费用管控与反欺诈的桥梁场景。

## 数据敏感性
报销数据含员工 PII（姓名、部门、费用）。**执行前先加载 `financial-local-safety` skill**，本地模式处理：原始文件留在本机，由本机脚本计算，只回传结果摘要（授权文件夹需关闭上传式全文索引与知识图谱抽取，否则该文件夹的文件会被上传）。

## 上层判据（不折旧 · 跨平台）
| 判据 | 规则 | 触发 |
|------|------|------|
| **唯一性** ⭐ | 发票号码全局唯一 | 重复 → risk |
| **唯一性（指纹）** ⭐ | (供应商,金额,日期,类别) 不重复 | 号不同要素同 → 变造重复 risk |
| **模式识别** | 同报销人发票号连续 ≥3 | 连号 → review |
| **边界** | 金额 ≤ 类别 P90×1.5 | 超额 → review/risk |
| **守恒（自检）** | Σ状态数 == 总单数 | 不等 → 分析错误 |

## Lessons Learned
### Do
- 唯一性核验必须多维：发票号 + 要素指纹（供应商+金额+日期+类别）双重比对。
- 连号、金额异常判 review（疑点），发票号重复、要素指纹重复判 risk（硬风险）。

### Don't
- 不要只比对发票号——变造重复会改号，只比号会漏网。
- 不要把连号直接判 risk——连号是疑点，需人工确认后定性。

### Common Failures
- 中文表头 BOM：用 `encoding="utf-8-sig"`。
- 金额字段为字符串：先 `float()` 转换再比较，异常兜底为 0。

### When to Ask the User
- 金额异常阈值（默认类别 P90×1.5）、连号判定长度（默认≥3）按客户口径确认。
- 是否将换人报销的同号发票视为更高风险，需确认业务规则。

## 判据
| 判据 | 规则 | 结果 |
|------|------|------|
| 号码唯一 ⭐ | 发票号归一化（去空格、全角转半角、去数字段前导零）后唯一 | 重复 / 变形重复 → 风险 |
| 跨期唯一 ⭐ | 与历史已报销发票池比对 | 跨期重复 → 风险 |
| 组合指纹 | 开票方税号 + 金额 + 开票日期相同而号码不同 | 换号重开 → 风险 |
| 拆分报销 | 同人、同开票方、同一天 ≥ 2 张，每张低于上限、合计超上限 | 风险 |
| 连号 | 同人、同开票方 ≥ 3 张号码连续 | 待核实 |
| 票面与日期 | 报销 ≤ 发票金额；报销不早于开票；开票至报销 ≤ 180 天 | 风险 / 待核实 |
| 交叉白名单 | 开票方行业 × 费用类别（餐饮 → 业务招待费） | 待核实 |
| 单笔上限 | 超过费用标准需审批；单笔上限无法解析，或为 0、负数时登记 `data_issues`，该类别逐笔标「费用标准无法解析 / 费用标准无效」，不当作不设上限 | 待核实 |
| 守恒 | Σ报销 == 通过 + 待核实 + 风险 | 自检 |

## 自检 vs 正式运行（边界 · 必读）

本 skill 捆绑了 `samples/` 夹具与 `self_check.py`，**仅用于验证脚本本身是否健康，绝不参与正式业务运行**。两者必须严格分开：

| | 正式运行 | 自检（回归测试） |
|---|---|---|
| 输入 | **用户当期数据**，路径由调用者显式提供 | 内置 `samples/{clean,error}/` 夹具 |
| 入口 | `check(报销+历史发票目录)` | `python scripts/self_check.py` |
| 目的 | 核对这套业务数据 | 验证脚本行为与黄金答案一致 |
| 何时跑 | 每次业务核对 | 脚本改动后 / 定期体检 |

**铁律**：
- 校验函数**不设指向 samples 的默认路径**——数据路径必填，调用者给什么就核什么，绝不会在漏传时静默去核样本、假报"全部通过"。
- `samples/` 是隔离夹具（体检用），不是"默认数据集"，正式运行永不读它。
- 自检是独立命令（`self_check.py`），和业务运行不共用入口。

> **自检怎么用**：`python scripts/self_check.py` → 对 `samples/clean/` 应全部通过（全平），对 `samples/error/` 应低于 100% 并正好抓出植入的错误，与 `samples/expected.json` 黄金答案逐项比对；一致则退出码 0（脚本健康），不一致则非 0（脚本可能已退化）。植错版是最强验证器——有确定的已知错误数与期望值，脚本一旦退化立刻暴露。

## 判据覆盖声明与已知盲区

> 本场景判据可捕获：**白名单、唯一性** 类错误。但每类自动校验都有其数学上的固有盲区——以下显式列出「判据抓不到什么」及对应处置。**「知道自己抓不到什么」比「能抓到什么」更是可信交付的证明。**

### 已知盲区（判据抓不到的错误类型）

| 盲区 | 关联判据 | 判据为何抓不到 | 处置 | 可闭合性 |
|------|:--:|------|------|:--:|
| 范围盲区 | 唯一性 | 只在「已登记」记录内查重，未登记项不进检查 | 登记源与业务源双向名单比对 | 🟢可自补 |
| **唯一性绕过变形** ⚠️ | 场景特有 | 空格/全半角/前导零变形绕过精确比对；拆分报销（一票拆两次各报一半，号码不重复） | 归一化后比对+模糊指纹（供应商+金额+日期组合键） | 🟢可自补 |

> **已接入** `scripts/invoice_dedup_v2.py`：号码归一化与组合指纹查重、跨期发票池比对、拆分报销、连号、开票方行业×费用类别、单笔上限与金额守恒。

### 可闭合性三档
- 🟢 **可自补**：加一段确定性检查即可闭合，零外部依赖——应直接实现。
- 🟡 **需外部锚点**：缺的是「第二个独立源」而非代码，须接入权威源（工商股权/银行/金税/合同）后方能校验——对客户标注为「需接入 X 源」。
- 🔴 **不可闭合**：结构上无验证基准（如员工自报项、需实物确认项），只能显式声明并交人工。

### 通用盲区补丁位（据本场景判据勾选）
- ☑ **范围完备性**：双向名单比对（A有B无 / B有A无 分别列示）——防「未进检查范围」的记录永远全绿
- ☐ **笔数守恒**：金额守恒之外加笔数守恒——抓成对反向错误
- ☐ **分向列示+分向限额**：正/负、双向单边分别设限——防净额掩盖
- ☑ **交叉白名单**：业务类型×允许值，白名单版本化+生效日——防「合法但不适用」
- ☐ **口径三元组**：时点+主体+准则声明 + 跨期衔接（本期期初=上期期末）——防口径错
- ☑ **归一化+模糊指纹**：去空格/全半角/前导零 + 组合键指纹——防唯一性绕过
- ☐ **外部锚点**：关键项引第三方独立源交叉验证——防同源错误
